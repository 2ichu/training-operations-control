# 시험용 샘플 파일 (가상 데이터)

로컬 Docker 환경(`http://localhost:8080`)에서 파일 업로드 기능을 시험하기 위한 파일 모음입니다.

> **모든 데이터는 가상입니다.** 이름·생년월일·번호는 실제 사람이나 기관과 무관하며, 주민등록번호 형식 값은 뒤 6자리를 가렸습니다(시스템은 앞부분에서 생년월일만 계산하고 주민번호를 저장하지 않습니다).
> **로컬 시험 전용입니다. 운영 서버에 올리거나 실행하지 마세요.** 시스템에는 삭제 기능이 없어서, 한번 넣은 가상 데이터는 DB를 초기화하기 전에는 남습니다.

## DB 시드와의 차이

| | DB 시드(`db:seed`) | 이 폴더의 샘플 |
|---|---|---|
| 목적 | 시스템이 동작하는 데 필요한 기준 데이터: 역할·권한·탐지규칙·최초 관리자 | 화면에서 **업로드해 보는** 시험 파일 |
| 실행 | 배포할 때마다 자동(`migrate`) | 사람이 직접 |
| 업무 데이터 | 만들지 않음(과정·훈련생 0건) | 시험용 가상 과정을 **선택적으로** 만드는 스크립트만 제공 |

이 폴더의 어떤 것도 자동으로 실행되지 않고, 앱 이미지에도 들어가지 않습니다.

> 현재 화면에서 파일을 올릴 수 있는 곳은 **공식 출결 대사(S29), 결과물 등록·재등록(S19), 운영일지(S17)** 세 곳입니다. 특이사항(S18)은 서버가 첨부를 지원하지만 화면에 첨부 기능이 없어서 시험할 수 없습니다. 첨부는 형식 제한이 없고 20MB 이하입니다.

## 1단계. 가상 과정 준비 (공식 출결 업로드의 전제)

공식 출결 업로드는 **그 과정에 등록된 확정 훈련생과 수업 회차**가 있어야 반영됩니다. 과정·훈련생·회차를 한꺼번에 넣는 업로드 기능은 없으므로 먼저 아래 가상 데이터를 앱에 만듭니다.

| 항목 | 값 |
|---|---|
| 과정 | `웹 프로그래밍 기초 1기` · 2026-09-07 ~ 2026-10-30 · 160시간 · 본관 301호 · 제출기한 2026-09-30 |
| 강사 | `한상우` (과정에 배정) |
| 회차(하루 한 회차, 09:00~18:00) | 1회차 09-21 / 2회차 09-22 / 3회차 09-23 / 4회차 09-24 |
| 훈련생(모두 확정) | 서주원 1998-03-15 · 박민재 1999-07-21 · 이하은 2000-01-09 · 정도윤 1997-11-30 · 최지우 2001-05-05 · 강예준 1996-09-12 |
| 내부 출결(대사할 때 비교 대상) | **1회차** 가온 출석 09:00, 나래 출석 09:00, 다솜 09:20 입실(자동 지각), 마루 출석 08:55, 라온 결석 확정, 바다 없음 / **3회차** 가온 09:00~18:00, 나래 09:00 |

### A. 스크립트로 한 번에 (권장)

앱이 떠 있는 상태에서 실행합니다. 시스템 관리자로 로그인해 시험 계정과 가상 과정을 만듭니다(화면에서 하는 것과 같은 API라 감사 기록이 남습니다). 접속 대상이 `localhost`·`127.0.0.1`·`web`이 아니면 실행을 거부합니다.

**호스트에 Node 20 이상이 있을 때**

```bash
# macOS / Linux
SAMPLE_ADMIN_LOGIN_ID=<관리자 아이디> SAMPLE_ADMIN_PASSWORD=<관리자 현재 비밀번호> node samples/setup-sample-data.mjs
```
```powershell
# Windows PowerShell
$env:SAMPLE_ADMIN_LOGIN_ID="<관리자 아이디>"; $env:SAMPLE_ADMIN_PASSWORD="<관리자 현재 비밀번호>"; node samples/setup-sample-data.mjs
```

**Node가 없을 때(Docker만 있을 때)**: 컴포즈의 `migrate` 이미지에 Node가 들어 있어 그것으로 실행합니다.

```bash
docker compose --env-file deploy.env run --rm --no-deps -v "$PWD/samples:/samples:ro" -e API_BASE=http://web:80 -e SAMPLE_ADMIN_LOGIN_ID=<관리자 아이디> -e SAMPLE_ADMIN_PASSWORD=<관리자 현재 비밀번호> migrate node /samples/setup-sample-data.mjs
```
(Windows PowerShell에서는 `$PWD/samples`를 `${PWD}/samples`로 쓰세요.)

- 관리자 비밀번호를 바꿨다면 **바꾼 현재 값**을 넣어야 합니다. 바꾸지 않았다면 `deploy.env`의 `SEED_ADMIN_*`가 그대로 유효합니다.
- 끝나면 시험 계정 두 개의 **임시 비밀번호가 화면에 한 번만** 출력됩니다. 첫 로그인 때 새 비밀번호로 바꾸게 됩니다.
  - `sample_ops` — 운영담당자: 공식 출결 대사·결과물 등록에 사용
  - `sample_ins` — 강사(한상우 강사에 연결): 운영일지 작성에 사용
- 이미 만든 적이 있으면 새로 만들지 않고 안내만 합니다. 처음부터 다시 하려면 로컬 DB를 초기화하세요(아래 "초기화").

### B. 화면에서 직접 만들기

위 표의 값을 화면에서 입력합니다. 대략 40번쯤 클릭이 필요해서 스크립트를 권장합니다.
관리자로 `sample_ops`(운영담당자)를 만든 뒤 그 계정으로 ① 강사 목록 → 강사 등록 ② 과정 목록 → 과정 등록(담당자는 `sample_ops`) ③ 과정 상세에서 강사 배정 ④ 강의 일정에서 회차 4개 등록 ⑤ 대상자 확인에서 훈련생 6명 등록 → 확인 시작 → 확정 ⑥ 일일 출결에서 위 "내부 출결"을 입력합니다. `sample_ins` 계정은 관리자 화면에서 역할 강사로 만들고 `한상우`에 연결합니다.

## 2단계. 공식 출결 업로드 시험

`sample_ops`로 로그인 → **출결 관리 → 공식 출결 대사** → 과정 `웹 프로그래밍 기초 1기` 선택 → 파일 선택 → **업로드·반영**. 엑셀 → CSV 순서를 권장합니다(두 파일은 서로 다른 회차를 다뤄서 순서가 바뀌어도 결과는 같습니다).

### `official-attendance_sheet_sample.xlsx` (1·2회차, 9월 21·22일)

기호: ○ 출석, × 결석, ◎ 지각, ▲ 조퇴, ▶ 외출(출석 처리), ▦15 공가(인정결석), `-` 아직 오지 않은 날, 빈칸 수업 없는 날. 23·24일은 CSV 시험용이라 비워 두었고, 25일은 수업 회차가 없는 날입니다.

| 결과 | 행 수 | 무엇이 일어나는가 |
|---|---|---|
| 공식으로 전환 | 3 | 1회차 가온(○=내부 출석)·다솜(◎=내부 지각)·라온(×=내부 결석): 내부 기록과 같아 공식 기록으로 바뀜(입·퇴실 시각은 유지) |
| 불일치(확인 필요) | 2 | 1회차 나래(공식 ×, 내부 출석)·마루(공식 ▲ 조퇴, 내부 출석): **내부 기록은 그대로 두고** 확인 필요 건이 생김 |
| 새로 기록 | 7 | 1회차 바다(내부 기록 없음)와 2회차 전원 6명: 공식 값으로 새로 기록(▶는 출석, ▦15는 인정결석) |
| 오류(미반영) | 2 | 25일: 그날 수업 회차가 없음(그 날짜는 한 번만 보고). `윤태민`: 과정에 등록되지 않은 훈련생(한 번만 보고) |

### `official-attendance_csv_sample.csv` (3·4회차)

| 결과 | 행 수 | 내용 |
|---|---|---|
| 공식으로 전환 | 1 | 3회차 가온: 내부 09:00~18:00, 공식 09:10~17:55(15분 이내) |
| 불일치(확인 필요) | 1 | 3회차 나래: 내부 09:00, 공식 09:40(40분 차이, 상태는 같아도 시각 불일치) |
| 새로 기록 | 4 | 3회차 다솜(지각), 4회차 라온(결석)·마루(인정결석)·바다(영문 코드 PRESENT) |
| 오류(미반영) | 6 | 생년월일이 다른 사람, 9회차 없음, 없는 훈련생, 알 수 없는 상태(`모름`), 시각 형식 오류(`25:99`), 같은 훈련생·회차 중복 |

업로드 뒤에는 **확인 필요 목록**에서 "공식-내부 정보 불일치" 건 3개(나래 1·3회차, 마루 1회차)를 볼 수 있습니다. 오류가 있는 행은 그 행만 반영되지 않고 나머지는 처리됩니다. 결과 표 아래 **업로드 이력**의 "상세"에서 행별 결과를 다시 볼 수 있습니다.

> 정각 배치가 돈 뒤에는 회차 운영일지 지연(RULE_03) 확인 필요 건이 추가로 생길 수 있습니다(가상 과정에 지난 회차의 운영일지가 없기 때문). 정상 동작입니다.

같은 파일을 **다시** 올리면 이미 반영된 행은 "변경 없음"으로 나오고, 내부 기록이 없던 곳만 처리됩니다(반복해도 안전).

## 3단계. 첨부 시험

| 화면 | 절차 |
|---|---|
| **제출현황(S19)** | `sample_ops` → 결과물 관리 → 제출현황 → 과정 선택 → 훈련생 행 "결과물 등록" → 제목과 원본 제출 일시 입력, 파일에 `submission_sample.pdf` → 등록 |
| **회차별 운영일지(S17)** | `sample_ins`(강사) → 과정 운영 → 회차별 운영일지 → 과정 선택 → 회차 "작성" → 교육내용·참여인원 저장 → 열린 창의 "첨부파일 추가"에 `operation-log_sample.txt`, `operation-log_photo_sample.png` |

첨부 목록의 파일명을 누르면 다운로드됩니다.

## 초기화 (처음부터 다시)

가상 데이터는 삭제 기능이 없으므로 **로컬 DB와 첨부 볼륨을 통째로 지웁니다**(관리자 계정도 새로 만들어집니다).

```bash
docker compose --env-file deploy.env down -v
docker compose --env-file deploy.env up -d
```

`-v`는 로컬 시험 데이터를 모두 지우므로 **실제 데이터가 있는 환경에서는 절대 쓰지 마세요.**

## 샘플 파일 다시 만들기(선택)

`pip install openpyxl && python3 samples/generate_samples.py` 로 이 폴더의 파일을 재생성합니다. 생성기와 파일의 값(훈련생 이름·생년월일·회차 날짜)은 `setup-sample-data.mjs`와 이 문서의 표가 서로 맞아야 결과가 위와 같이 나옵니다.
