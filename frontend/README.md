# Frontend (React + TypeScript + Vite)

> 운영에서는 빌드 결과를 nginx 로 제공하고 `/api` 를 백엔드로 넘긴다(`Dockerfile`, `nginx.conf`, 배포 절차는 [docs/DEPLOY.md](../docs/DEPLOY.md)).

훈련과정 통합관리 및 내부통제 시스템의 웹 화면. 화면 명세는 `system-design.md` STEP 3·7·7-A, 권한은 `baseline.md` 4-2 를 따른다.

## 실행

1. 백엔드를 먼저 띄운다(`backend/README.md` — `migrate:up`, `db:seed`, `npm run start:dev`, 기본 포트 3000).
2. `npm install` 후 `npm run dev` — 개발 서버가 `/api` 요청을 백엔드로 넘긴다(`vite.config.ts`, 대상 변경은 `API_PROXY_TARGET`).
3. `npm test`(vitest + Testing Library, jsdom), `npm run lint`, `npm run build`.

세션은 백엔드가 발급하는 httpOnly 쿠키(SameSite=Lax)라 **화면과 API 가 같은 출처**여야 한다. 개발은 Vite 프록시, 운영은 리버스 프록시로 정적 파일과 `/api` 를 한 도메인에서 제공하는 것을 전제로 한다.

## 구조

- `src/api` — `client.ts`(fetch 래퍼, 오류 응답 `{ code, field, message }` → `ApiError`, 401 이면 세션 만료 처리), `useApi.ts`(조회 훅), `types.ts`(응답 타입)
- `src/auth` — 세션 상태의 원본은 서버(`GET /auth/me`)이며 브라우저 저장소에 사용자·권한을 두지 않는다. `can(screenId, action)`은 메뉴·버튼 노출용일 뿐이고 통제는 서버가 요청마다 재검증한다(system-design 2.3).
- `src/menu.ts` — system-design 3.2 메뉴 구조. 각 항목은 해당 화면의 조회(R) 권한이 있을 때만 보인다(S20 은 S19 권한으로 판정).
- `src/routing/guards.tsx` — 로그인 필수, 초기 비밀번호 상태면 변경 화면만 허용(baseline 10-2 #5), 화면 권한 없으면 안내.
- `src/labels.ts` — 상태 코드 → 표시명(baseline 3절 상태값 사전).

## 구현 범위

- 로그인·로그아웃, 세션 만료 시 로그인 화면으로 복귀, 본인 비밀번호 변경(강제 변경 포함)
- 역할별 메뉴·레이아웃, 권한 없는 화면 안내
- **S01 대시보드**: 날짜 회차 목록, 확인 필요 상태별 건수 + 최근 발생 건(관련 훈련생 "외 N명" 축약), 미처리 건수. 필터(날짜·과정·내 담당 건만)는 URL 쿼리에 유지된다. 담당자 필터는 사용자 목록 조회(S25)가 시스템 관리자 전용이라 확인/조치 처리 권한(S22:A)이 있는 사용자에게 "내 담당 건만"으로 제공한다.
- **확인/조치(S22·S23·S24)**
  - S22 목록: 발생일 범위·과정·탐지유형·훈련생명·상태(기본 진행중만)·내 담당 필터, 선택 건 "나에게 배정"(배정 가능한 사용자 목록 API 가 시스템 관리자 전용이라 본인 배정만 제공)
  - S23 상세: 탐지 근거를 사실 그대로 나열(회차·훈련생 ID 는 이름으로 표시, 해석 문구 없음), 관련 훈련생, 확인·조치 내용, 현재 상태에서 가능한 처리만 폼으로 제공(baseline 3-4 전이표), 처리이력. 다른 사용자가 먼저 처리해 409 가 오면 안내 후 최신 상태를 다시 불러온다
  - S24 조치이력: 기간·과정·처리 유형·내 담당 필터
- **과정(S15·S16)**
  - S15 목록: 과정명·상태·기간·담당자(운영담당자만) 검색, 확정 훈련생 수, 신규 등록(S16:C)
  - S16 등록·수정: 필수값·기간 검사, 담당자는 `GET /courses/manager-candidates`(활성 OPS_MANAGER)에서 선택, 수정은 바뀐 필드와 사유(선택)만 보낸다. 종료·중단 과정은 수정 불가
  - S16 상세: 현재 상태에서 가능한 전환만 버튼으로(모집 시작·운영중 전환·종료·중단, baseline 3-1). 운영중 전환 시 확정 훈련생 0명이면 경고 후 재확인, 중단은 사유 필수, 종료는 체크리스트를 다시 검사해 필수 차단이 있으면 막고 경고만 있으면 사유를 받는다(baseline 9절). 탭: 훈련생(등록 상태별 인원) / 강사배정 / 교육일정 / 종료 체크리스트(S16:A — 항목별 확인 화면 링크)
- **훈련생(S02~S06)**
  - S02 대상자 확인: 상태 탭(대상자 확인 / 확정 / 수료·중도포기·제적 / 취소), 과정·성명·신청일 검색, 행별 처리(확인 착수·확정·반려는 사유, 수료·중도포기·제적은 사유 필수 — 최종 상태). 확정 탭에서 과정을 고르면 수료 판정 확인 후보(D-05 §6, 가중 출석률 기준 미달)를 보여준다 — 판정은 사람이 한다
  - S03 훈련생 목록: 과정·상태·성명·연락처(4자 이상) 검색, 연락처·생년월일은 마스킹 값만
  - S04 등록: 성명(·생년월일)으로 기존 인물을 먼저 찾아 같은 사람이면 새 과정에만 등록, 아니면 신규 인물로 등록(신청 상태). 이미 유효하게 등록돼 있으면 기존 등록 건으로 안내. 정보 수정은 마스킹 값을 채우지 않고 바꿀 항목만 입력 + 사유 필수
  - S05 상세: 여러 과정에 등록된 경우 등록 건을 골라 출결요약·결과물을 그 과정 기준으로 본다. 탭: 등록이력 / 출결요약(미출결·휴강 표시) / 결과물 / 확인필요 관련이력(S05:A)
  - S06 변경이력: 훈련생명·대상 구분·기간 검색, 바뀐 필드만 전 → 후로 표시(감사 컬럼 제외)
- **출결(S07~S10)**
  - S07 일일 출결: 조회일(기본 오늘)·과정·회차 선택, 확정 훈련생 전체 명단(기록 없는 훈련생은 계산값 "미출결" — 점선 배지, C1). 선택한 미출결은 입실 확인·결석 확정(결석 확정은 S07:A, 강사 불가), 기록이 있고 퇴실이 빈 행은 퇴실 확인(공식 출결 행은 제외 — 읽기전용). 처리 시각을 지정하지 않으면 현재 시각. 다른 사람이 먼저 처리한 건은 건너뛰었다고 안내. 휴강 회차는 명단 없이 안내만
  - S08 과정별 출결: 훈련생 × 회차 매트릭스(약어 배지 + 범례, 훈련생 열 고정), 출석률. 기록 셀은 S09, 미출결 셀은 그 회차의 S07 로 이동
  - S09 출결 수정(모달): 바뀐 필드·사유(필수)·기대 수정시각만 보내고(낙관적 잠금), 충돌이면 최신 값을 다시 불러온다. 수정 권한(S09:U)이 없으면 상세만
  - S10 출결 수정이력: 과정·훈련생명·기간 검색, 회차와 바뀐 필드(전 → 후), 시스템 수정은 "시스템"으로 표시
- **강사·일정(S11~S14)**
  - S11 강사 목록: 성명·상태 검색, 마스킹 연락처, 담당 과정 수. 신규 등록(S12:C)·배정 관리(→S13). 강사 계정은 본인만
  - S12 강사 등록·상세·수정: 연결된 로그인 계정은 읽기전용 표시(계정 관리는 S25). 수정은 연락처를 채우지 않고 바꿀 때만 입력 + 사유 필수. 비활동 전환 시 진행 중 배정이 남아 있으면 대체 배정 안내
  - S13 강의 일정/교육일정: 하나의 화면, 진입점 둘(system-design 3.4) — 강사 관리 메뉴는 캘린더 우선(월 단위, 좁은 화면에선 일정 있는 날만 세로 목록), 과정 상세에서 들어오면(`?course_id=`) 회차 순 목록 우선 + 강사 배정 패널. 회차 추가(해당 회차에 유효 배정된 강사만 선택)·수정·휴강(사유 필수)·강사 재배정(사유 필수), 배정 추가(과정 전체/특정 회차)·취소(사유 필수, 남은 예정 회차 경고). 같은 강사·같은 시간대 회차가 있으면 저장 후 경고만(차단하지 않음). 종료·중단 과정은 변경 버튼 없음. 회차(목록·캘린더)를 누르면 그 회차의 운영일지(S17)로 간다
  - S14 강사 변경이력: 강사·대상 구분·기간 검색, 대상(강사, 배정은 과정·회차 범위)과 바뀐 필드(전 → 후)
- **운영일지·특이사항(S17·S18)**
  - S17 회차별 운영일지: 과정(필수)·회차·교육일·작성여부 검색, 회차별 작성 여부(미작성은 계산값 — 점선 배지, 휴강 회차는 대상 아님). 작성은 담당 강사(교육내용·참여인원 필수, 특이사항 선택), 수정은 작성 강사 또는 운영담당자 검수(바뀐 필드만). 저장 후 첨부파일 추가(추가만 가능 — append-only)·다운로드. "특이사항으로 등록"은 과정·회차·특이사항 내용을 채운 S18 등록 폼으로 넘긴다. 종료 체크리스트 "운영일지 미작성"·S13 회차 클릭에서 들어온다
  - S18 특이사항: 과정·회차·상태 검색, 카테고리·상태 배지, 연결된 확인 건의 현재 상태(참고 열, S23 링크). 등록(강사·운영담당자), 수정·조치완료(운영담당자), "확인 필요로 전환"(운영담당자·관리자/책임자 — 관련 훈련생 선택 가능, 만든 뒤 S23 으로 이동). 활성 확인 건이 있으면 전환 버튼을 숨기고, 그 사이 누가 먼저 전환해 409 가 오면 새로 만들지 않고 안내한다. 조치완료는 연결 확인 건과 독립(H6)
- **결과물(S19~S21)** — 결과물은 운영담당자가 대신 등록한다(D-01)
  - S19 제출현황: 과정(필수)·훈련생명·검토상태 검색, 확정 훈련생 × 결과물(행 없으면 계산값 "미제출" — 점선 배지). 제출일(원본, 수기 입력)과 등록일시·등록자를 구분해 표시. 결과물 등록(훈련생·제목·원본 제출 일시·파일 필수), 재등록(버전 증가·검토 대기로, 새 파일은 새 버전으로), 행별 검토(→S21). 행은 저장됐는데 파일 업로드만 실패하면 그대로 안내. 강사는 조회만
  - S20 미제출: 결과물이 없는 확정 훈련생 + 기한후제출, 과정 제출기한·경과일수(미제출=오늘−기한, 기한후제출=제출일−기한), 마스킹 연락처, 조회 전용
  - 제출기한(D-04): 과정 등록·수정에서 과정 공통 날짜로 정한다. 그날 24:00 이후 제출은 기한후제출로 자동 판정되고, 기한을 바꾸면 기존 결과물도 재판정된다(과정 상세에 재판정 건수 안내)
  - 검토이력(S21 진입 목록): 과정별 결과물을 검토상태로(기본 대기) 모아 보고 상세로 이동. 종료 체크리스트 "결과물 미검토"도 여기로 연결
  - S21 결과물 검토: 버전별 파일(다운로드)과 버전별 검토이력을 나눠 보여주고, 현재 버전에 검토결과(적합·보완요청·부적합)·검토내용 저장. 검토는 운영담당자만, 관리자/책임자·시스템 관리자는 읽기만, 강사는 접근 불가
  - 훈련생 상세(S05) 결과물 탭의 제목 → S21
- **시스템 관리(S25~S28)**
  - S25 사용자: 이름·로그인ID·역할·상태 검색, 등록(1인 1역할, 강사 역할은 연결 강사 필수)·수정(바뀐 필드만)·비활성화·비밀번호 초기화. 등록·초기화 때 서버가 만든 임시 비밀번호를 한 번만 보여 주고 첫 로그인 때 변경을 강제한다. 마지막 활성 시스템 관리자의 비활성화·역할 변경은 서버가 막는다(P5-09)
  - S26 권한: 역할 × 화면 × 기능(C/R/U/D/A) 매트릭스, 화면 행 단위 범위(전체/본인 담당). 바꾼 화면을 표시하고 저장은 역할 전체 교체(바로 적용, 감사로그 1건). S20 은 S19 권한을 따르므로 편집하지 않는다. 시스템 관리자 역할에서 S26 조회·저장은 뺄 수 없다(P5-09)
  - S27 감사로그: 기간 필수(비우면 최근 30일, 최대 1년)·행위자 구분·사용자(시스템 관리자만)·대상 테이블·액션 검색, 행 → 변경 전/후(바뀐 필드 강조, 배열·기타는 원문 JSON). 조회 자체도 감사로그에 남는다. 관리자/책임자도 조회 가능
  - S28 탐지규칙: 규칙별 기준값·사용 여부 조정(바꾼 값만, 1~100000 정수, 사유 필수 — P5-02). 초기 상태는 표시만, MANUAL 은 수정 불가
- system-design 3.2 메뉴의 모든 화면이 구현되어 "준비 중" 자리표시 화면은 없앴다.
